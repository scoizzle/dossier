- =========================== Django 1.10.7 release notes =========================== [53066617]
- A maliciously crafted URL to a Django site using the :func:`~django.views.static.serve` view could redirect to any other domain. The view no longer does any redirects as they don't provide any known, useful functionality. [ef761567]
- Also, if a developer relies on ``is_safe_url()`` to provide safe redirect targets and puts such a URL into a link, they could suffer from an XSS attack. [9786d31d]
- Bugfixes ======== [6c84539cac9c976c-7] [3c4a8ca8]
- CVE-2017-7233: Open redirect and possible XSS attack via user-supplied numeric redirect URLs ============================================================================================ [fd3f496c]
- CVE-2017-7234: Open redirect vulnerability in ``django.views.static.serve()`` ============================================================================= [01b23447]
- Django 1.10.7 fixes two security issues and a bug in 1.10.6. [f7efc412]
- Django relies on user input in some cases (e.g. ``django.contrib.auth.views.login()`` and :doc:`i18n </topics/i18n/index>`) to redirect the user to an "on success" URL. The security check for these redirects (namely ``django.utils.http.is_safe_url()``) considered some numeric URLs (e.g. ``http:999999999``) "safe" when they shouldn't be. [a5c072eb]
- Note, however, that this view has always carried a warning that it is not hardened for production use and should be used only as a development aid. [473596e3]
