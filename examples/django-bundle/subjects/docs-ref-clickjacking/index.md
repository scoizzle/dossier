- Limitations =========== [2d2b8d6e6fcd3452]
- Modern browsers honor the `X-Frame-Options`_ HTTP header that indicates whether or not a resource is allowed to load within a frame or iframe. If the response contains the header with a value of ``SAMEORIGIN`` then the browser will only load the resource in a frame if the request originated from the same site. If the header is set to ``DENY`` then the browser will block the resource from loading in a frame no matter which site made the request. [f5c5b014]
- Note that you can use the decorators in conjunction with the middleware. Use of a decorator overrides the middleware. [32fd0de3]

- [eeb8f4e4] Preventing clickjacking =======================
- [689e1f3a] Setting ``X-Frame-Options`` for all responses ---------------------------------------------
- [3fbf2efb] Setting ``X-Frame-Options`` per view ------------------------------------
- [a3aec0ee] Suppose an online store has a page where a logged-in user can click "Buy Now" to purchase an item. A user has chosen to stay logged into the store all the time for convenience. An attacker site might create an "I Like Ponies" button on one of their own pages, and load the store's page in a transparent iframe such that the "Buy Now" button is invisibly overlaid on the "I Like Ponies" button. If the user visits the attacker's site, clicking "I Like Ponies" will cause an inadvertent click on the "Buy Now" button and an unknowing purchase of the item.
- [47f9d03e] The ``X-Frame-Options`` HTTP header will only be set by the middleware or view decorators if it is not already present in the response.
- [ddf17557] The ``X-Frame-Options`` header will only protect against clickjacking in `modern browsers`_.
- [d1b4f25d] The clickjacking middleware and decorators provide easy-to-use protection against `clickjacking`_. This type of attack occurs when a malicious site tricks a user into clicking on a concealed element of another site which they have loaded in a hidden frame or iframe.
